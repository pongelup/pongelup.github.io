# leandropongeluppe.com (GitHub Pages version)

Static replacement for the Google Sites website, with the same look, pages, URL paths, and content.
The HTML in this folder is generated by `build.py` from the data and content files, and the generated
HTML is committed so GitHub Pages serves it directly (no Jekyll, no build step on GitHub).

## Layout

| Path | What it is |
|---|---|
| `data/site.yml` | Site name, navigation, footer icons, StatCounter settings |
| `data/news.yml` | News items. `build.py` merges them with `data/media.yml` into one dated "News and Media" list (newest first, duplicates by URL removed): all of it on Practice & Media (`/extension/#news`), the first 3 on Home. `/news/` only redirects there |
| `data/publications.yml` | Published papers: `international`, `brazilian`, `book_chapters` (citation and short description; text only, no figures) |
| `data/working_papers.yml` | Working papers, grouped by research pillar, ordered by closeness to publication (the CV lists two more papers that the site leaves out) |
| `data/media.yml` | Media mentions (`english`, `portuguese`), merged into the "News and Media" list on Practice & Media |
| `content/<page>.yml` | Free text of each page (banner photo, title, SEO description, "Last update" line); the Research pillar cards live in `content/research.yml` |
| `templates/` | Jinja2 templates (`base.html` holds header, footer, StatCounter) |
| `assets/css/site.css` | Styles (PT Sans + Merriweather, as in the Google Sites theme) |
| `assets/img/` | Images (banners, covers, paper figures, social icons); `assets/img/sdg/` holds the UN SDG icons (`sdg_01.png` ... `sdg_17.png`) |
| `assets/papers/`, `assets/reports/`, `assets/slides/` | PDFs linked from the site (papers, technical reports, class slides), moved here from Google Drive |
| `assets/cv/Leandro_Pongeluppe_CV.pdf` | CV PDF shown on the CV page (compiled from the CV Overleaf repo) |
| `index.html`, `home/`, `news/` (redirect), `cv/`, `research/`, `teaching/`, `extension/`, `cia-framework/`, `personal/`, `404.html` | Generated pages (do not edit by hand) |
| `CNAME` | Custom domain `www.leandropongeluppe.com` |
| `PENDING_FIXES.md` | Audit findings waiting for Leo's approval |

Text fields accept inline HTML (`<i>`, `<b>`, `<a href="...">`). Keep YAML indentation (two spaces) and
wrap text containing a colon or quotes in double quotes, or use a `>-` block as in the existing entries.

## Add a news item

Edit `data/news.yml` and put a block at the top of `items` (newest first):

```yaml
items:
  - date: "October 2026"
    text: "New paper in <i>Journal Name</i> with Coauthor One: \"Paper title.\""
    link: "https://doi.org/10.xxxx/xxxxx"
    link_text: "Read it"
```

Dates may be "October 2026", "October 9th, 2026.", or "9 de outubro de 2026."; the list is sorted by date.
If the same link is also in `data/media.yml`, the item shows once, with the text from `data/news.yml`.

## Add a published paper

1. Drop the PDF in `assets/papers/` with a clean name: `YEAR_JOURNAL_Author_Short_Title.pdf`
   (for example `2022_SMJ_Pongeluppe_Favela_Effect.pdf`). Paper and appendix merged in one PDF is fine.
2. Edit `data/publications.yml` and add a block at the top of `international` (or `brazilian`, `book_chapters`):

```yaml
  - authors: "Pongeluppe, L. S., & Coauthor, A. (2027)."
    title: "Paper title."
    url: "/assets/papers/2027_JOURNAL_Pongeluppe_Short_Title.pdf"
    after: "<i>Journal Name.</i> 12(3): 45-67."
    doi: "https://doi.org/10.xxxx/xxxxx"
    note: "Award line, shown in small print (optional)."
    description: "Two sentences: setting, data, and approach."
```

Published papers are text only (no figures); figures appear only on working papers.

3. Rebuild (`python build.py`). The title and a "PDF" link point to the local file; the DOI link stays.

Reports go in `assets/reports/` (linked from `content/extension.yml`) and class slides in `assets/slides/`
(linked from `content/teaching.yml`), the same way.

## Add a working paper

Edit `data/working_papers.yml`. Add a block under the right `topic`, keeping the order by closeness to
publication (second-round R&R, first-round R&R, submitted, working paper):

```yaml
      - title: "Paper title"
        coauthors: "in collaboration with Coauthor One and Coauthor Two."
        status: "Second round at Journal Name."
        description: "Two sentences: setting, data, and approach. No results, numbers, or effect directions."
        links:                        # optional
          - { url: "https://papers.ssrn.com/...", label: "Available at SSRN" }
        image: my-figure.png          # optional; put the file in assets/img/ (no SDG icons in figures)
        image_alt: "Describe what the figure depicts"
        caption: "Neutral description of the setting (not a result)."
```

## Research pillar cards and SDG icons

The three cards at the top of the Research page live in `content/research.yml` (`program`). Each card has
`image` (optional photo in `assets/img/`), `text`, and `sdgs` (a list of SDG numbers). Icons are read from
`assets/img/sdg/sdg_NN.png` (two digits, for example `sdg_06.png`) and appear only when the file exists.

## Banners

Each page sets its banner photo in `content/<page>.yml` (`banner:`, plus an optional `banner_alt:` that
describes the photo). The banners alternate page by page in navigation order; to use a new photo, put it in
`assets/img/` and change `banner:`.

## Update the CV

1. Edit and compile the CV in the CV Overleaf repo (`Webpage\CV Overleaf`).
2. Copy the compiled PDF over `assets/cv/Leandro_Pongeluppe_CV.pdf`.
3. Change `cv_updated` in `content/cv.yml` (and the button text in `content/home.yml`), then rebuild.

## Add a media item

Copy a block in `data/media.yml` to the top of `english` or `portuguese` and edit it. It appears in the
"News and Media" list on Practice & Media, sorted by its date.

## Rebuild

```bash
python -m pip install pyyaml jinja2   # once
python build.py                        # writes all pages and checks internal links
```

`python build.py --check` only checks internal links of the pages already built.

## Preview locally

```bash
python -m http.server 8000
```

Then open http://127.0.0.1:8000/ in a browser. (The local server shows its own 404 page;
GitHub Pages uses `404.html`.)

## Publish

1. Commit the changed data files and the regenerated HTML.
2. Push to the GitHub repository; in Settings > Pages, set the source to the `main` branch, root folder.
3. The `CNAME` file sets the custom domain. At the DNS provider, point `www` (CNAME record) to
   `<github-username>.github.io` and follow GitHub's instructions for the apex domain. Turn on "Enforce HTTPS".

## Tracking

StatCounter project 12004789 (the same project the Google Sites version used) is loaded on every page
from `templates/base.html`, with the original settings (`sc_invisible=1`, `sc_security="4ceffa89"`,
`sc_https=1`). No Google Analytics ID was found on the old site, so none is included; to add one later,
set `ga4_id` in `data/site.yml`.
